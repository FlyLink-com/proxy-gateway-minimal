## What Changed And Why

PR #169 converted the Aliyun Subscription Control Platform promotion into a
clear gate model:

```text
Gate A live inventory
Gate B source-state decision
Gate C private state-copy or clean-start validation
Gate D public-boundary dry run
Gate E DNS / production distribution promotion
Gate F observation / rollback / cleanup
```

The main reason was to stop treating Aliyun promotion as a single deployment
step. Promotion now has explicit inventory, source-state, firewall, validation,
public-boundary, DNS, and rollback gates.

PR #170 added repository-only channel measurement investigation reports. It can
classify safe measurement bundles, such as the held Hysteria2 measurement, into
advisory investigation patterns without running probes or touching nodes.

PR #171 added repository-only channel candidate comparison plans. It can combine
safe investigation reports with dry-run channel config summaries and recommend
non-held candidate families such as TUIC or VLESS/XUDP for a future separately
approved canary.

PR #172 recorded Aliyun Gate A live inventory. The record showed the Aliyun
candidate app and loopback Nginx are healthy privately, while promotion remains
blocked because DNS points to stopped AWS, provider firewall is too broad, source
state is not available, and stale node config remains.

PR #173 turned Gate A findings into the Gate B source-state and
provider-firewall plan. It recommends clean-start Aliyun control plane unless
the operator explicitly requires historical subscription state preservation.
It also separates provider-firewall hardening from source-state recovery,
rollback-start, private validation, and DNS promotion.
