## Issue alignment and next gate

- [#557](https://github.com/gccwebos-com/proxy-gateway-minimal/issues/557) remains the parent for commercial-pilot Operations work. Keep the existing Admin shell and domain stores; the first proposed functional slice is an owned, protected **order read list/detail** linking payment, Coins, entitlement, and delivery states.
- [#558](https://github.com/gccwebos-com/proxy-gateway-minimal/issues/558) and [#559](https://github.com/gccwebos-com/proxy-gateway-minimal/issues/559) are still open, but their 2026-08-30 descriptions include pre-#729 claims about the frontend login and legacy monitor. Reconcile those statements against this Git reference before using them as an implementation checklist. Their remaining role, lifecycle, metric, and freshness gaps are not closed by this inventory.
- [#560](https://github.com/gccwebos-com/proxy-gateway-minimal/issues/560) continues to track general Admin action audit. Do not enable compensation, retry, entitlement change, or other operator write controls merely because a read page exists.

The next Risk A inventory must name each target and command, freeze the read-only scripts and output schema, and obtain a new one-use operator approval. It should prove current Admin static identity, backend pointer/process/code identity, database schema identity, non-secret commercial flag classifications, and rollback custody. It must stop if release units cannot be independently bound. Browser login/query acceptance, payment settlement, and sample-to-rollup accounting need their own scoped validation; no historical note substitutes for them.
